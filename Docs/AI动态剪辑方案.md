# RunOverlay AI 动态剪辑方案（实施讨论稿）

## 1. 目标与边界

在现有「导入 DJI/影石视频 → 匹配 FIT/GPX → 配置跑步蒙层 → 批量导出」之后，增加独立的「智能成片」工作流：从**已经导出、带数据蒙层且保留原声的视频**中挑选片段，自动生成一条以**你自己的口播为主线**的跑步 Vlog。用户先审阅并调整时间线，再导出最终成片。软件始终保留「原视频 → 单条带蒙层导出视频 → 剪辑片段 → 最终成片」的来源关系。

第一版不改写原视频、不重新计算或烧录蒙层、不自动发布、不自动生成未经用户确认的虚构镜头。原有单视频批量导出继续独立工作；智能成片读取它们的输出文件，保存自己的剪辑草稿和素材引用。若项目的 FIT/GPX 还在，可用已匹配的运动时间辅助发现上坡、冲刺等节点；没有运动文件，也能仅凭导出视频完成基础剪辑。

**产品硬约束**：只使用在中国大陆可正常访问的模型服务，不要求翻墙；原视频中的本人口播优先于配乐和画面快切，不做声音克隆、AI 代说、换词或仅凭摘要重写你的发言。口播是否删除、对一整句进行大幅缩短，由用户确认；默认保留完整句意、语气与自然停顿。设备未保留音轨或导出时关闭「保留原始音频」的片段，不能伪装为含有口播。

**时长原则**：不设置默认成片时长，也不设置人工规定的最长成片时长或单段镜头时长。自动剪辑根据可用素材、叙事完整性和用户保留的片段决定成片长度；用户随时可在时间线上增加、延长或删除片段。目标时长如需提供，只作为可选的节奏参考，不是强制裁切条件。实际导出仍受源素材长度、磁盘空间、编码能力及文件系统限制。

**项目现状与必须补的衔接层**：当前导出队列保存目标路径和状态，但完成后清空队列，并没有在项目中持久记录「这条导出片对应哪条原片」。因此不能直接承诺打开项目就能自动找回历史导出。第一阶段先在导出成功时写入可重定位的「导出成果清单」，并为旧导出提供手动选择/批量重连；只按文件名后缀推测对应关系可以做提示，不能默认认定。

「按我之前的风格」分两层处理：跑步聚焦、轨迹和数据蒙层构成当前已知的**视觉风格**；叙述语气、习惯的口播长度、喜爱的切镜频率与音乐节奏，需要用户提供 2～5 条本人满意且保留本人声音的 Vlog，或在首批草稿中保留/删除几段供软件学习。仅靠现有导出视频无法可靠推断用户以往的剪辑决策。

## 2. 用户操作流程

1. 选择素材：优先引用本项目**新流程记录且仍能访问**的导出成果；也能手动导入其他已带蒙层的 MP4/MOV。对于此前未记录的成果，用户手动确认与原视频的对应关系。列表显示缩略图、时长、比例、原声音轨是否存在、疑似本人口播、是否缺失；不扫描输出目录中的其他文件当成原片。
2. 选择目标：设置 16:9/9:16 等画幅、「口播纪实 Vlog / 跑步记录 / 风景补画面」节奏预设及是否使用用户提供的音乐。成片时长默认「由素材决定」；可选建议时长不强制截断口播或限制最终导出。
3. 点击「分析素材」：先提取原声、转写口播并生成按语句分段的文字稿；再抽帧粗筛画面。界面显示预计上传的音频分钟数/视频帧数及预算上限，用户明确同意后才调用国内云模型；拒绝上传或断网时回退本地筛选和人工标记口播。
4. 生成 1～3 条草稿：以口播句子为骨架，列出字幕/转写内容、原视频文件名、片段入点/出点、补画面镜头、推荐理由与运动数据提示；每句可以直接试听并锁定。
5. 审阅时间线：语句级调入出点、拖动补画面与镜头顺序、锁定片段、剔除/替换候选、调节原声/配乐/环境声及撤销重做；重新生成时保持已锁定的口播与人工调整。
6. 预览并导出：先快速生成低分辨率预览，再由本地 AVFoundation 精确导出最终视频；导出任务继续沿用现有进度与后台机制。

「后台继续」只收起分析/渲染面板，不取消任务；应用退出后是否恢复未完成任务属于第二阶段。分析失败不得阻塞现有视频导出。默认可在本地生成保守草稿；需要自动理解本人讲话和画面时提供国内云服务并明确取得上传同意，不填写密钥或断网仍可编辑与导出。

## 3. 选段策略：口播主线 + 本地筛选 + 国内视觉模型

### 先锁定口播，再决定画面

- 从**已导出视频**读取保留的原声音轨，先检测说话区域和停顿，得到带毫秒级时间轴的转写文字稿。若转写模型不提供稳定的字/词级时间戳，另外用语音对齐得到句边界，不把一句话中途切断。
- 默认锁定全部可以确认是你本人讲述的完整语句，允许移走超过设定阈值的空白和明确重复的废话，但**删除有人声的句子必须进入待确认清单**；无法确定说话者时先保留并标「待听审」，不能自动当成噪声。多人说话时允许指定谁是主讲人，不把同伴的声音冒认为你的口播。
- 对已识别句子做语义分段，例如「出发/天气与路况 → 跑步过程 → 上坡或难点 → 当下感受 → 收尾」。叙事结构必须服从实际说过的话，没有收尾口播时可以用现场声音或画面收尾，不由模型创作你没说过的结论。
- B-roll（跑步动作、风景、带数据蒙层的镜头）在口播句间替换画面或覆盖同一段口播；**口播音频轨道继续播放**，画面换镜不能带走原声。音频引用必须保留 `sourceExportID + audioIn/audioOut` 和经视频导出校准的时间位置。
- 若补画面本身也含重要口播，禁止直接压到已有口播上；可先当作新的口播段或只用其画面并显式静音这段补画面的重复声音。用户可试听、改字、标为本人/他人和锁定语句，模型重分析不覆盖人工确认。

### 本地粗筛（默认零模型费用）

- 按视频原时间生成低清代理和缩略图；每 3～5 秒抽 1 帧，检测场景变化时额外取关键帧。不上传完整 4K 视频。
- 本地计算模糊、黑屏、过曝、稳定度、运动强度、构图与相似片段；音频除口播检测外，再提取环境声峰值或节拍位置。苹果 Vision/AVFoundation 的可用能力优先，识别人脸等信息只在用户明确需要时启用。提取原声音频供识别使用**不改变**原视频或原声轨道。
- 用原有 FIT/GPX 时间映射推导里程、配速变化、心率、爬升坡段、抵达终点；此类事件只是候选加分，不能证明画面一定精彩。对新导出成果，映射为 `运动时间 = 原视频已校准拍摄时间 + 导出文件内秒数`；现有全段导出可沿用这一映射。手动导入且没有可靠关联的文件，只做视觉/音频分析，不凭文件名猜测运动数据。
- 对已有数据蒙层做遮挡避让：视觉判断与最终裁切不能切掉轨迹、里程、时间。横转竖若不能保证画面主体和蒙层都完整，标为「需要人工检查」，默认留黑边而不破坏内容。
- 每个候选片段保留 `sourceURL + startSeconds + endSeconds + scoreFeatures`；时间戳始终指向**导出后的视频**，不直接套用原片时间。

### 视觉模型精排

只向国内模型提交候选片段的少量关键帧和时间戳（必要时附授权后的低清短视频），请求判断：人物/环境是否清楚、画面与**已转写口播句子**是否相关、镜头重复情况及其适合放在 Vlog 哪个段落。**离散图片不能可靠判断完整动作、步态连续性或稳定度**；这些先由本地连续帧分析，必要时再让经用户授权的视频模型复核。模型不改写转写稿、不发明台词，只返回有限、可校验的结构化分数与理由，不直接生成或操作视频。

镜头推荐的示例权重：口播语义贴合 40%、本地画质 25%、运动事件 20%、镜头多样性 15%；**口播音频锁定是硬约束，不参与加权竞争**。预设可以调分值，硬规则优先于分数：去掉严重模糊/黑屏、不越界、不过度重复、不超预算。运动数据连续显示时，默认**按真实运动时间递增排列**，不能为制造“冲线”而让里程或心率时间倒退。口播讲述过去事情时，补画面可以明确用作回忆镜头，但不能把一段运动时间倒退伪装成实时进度。

### 动态剪辑（规则可调，非随机特效）

依据**实际口播顺序**组织「开场交代 → 跑步过程 → 强事件/上坡/节奏抬升 → 收尾」，无口播的自然段落用环境声与运动画面衔接；素材不包含某类镜头就调整结构，不为了凑固定时长而删掉你的表达。以干净直切为主，只在句间或画面上切镜，不因音乐重拍切掉句中语音。每段语音边界和音频平滑区间由对齐结果与实际试听决定，镜头长度不设硬性上下限。第一版实现视频直切、**跨画面的持续口播轨道**、音量包络和环境声淡入淡出；复杂转场、自动变速和智能竖屏重构后置。

## 4. 国内模型选型、性价比与调用策略

明确要求：**只使用国内可直接访问的模型平台**，不使用 OpenAI、Gemini 或要求翻墙的境外接口做产品默认路线。模型只做转写、语义理解和镜头推荐，不负责编码最终成片；前后两端的媒体处理仍在 Mac 本地执行。

| 环节 | 首选试点 | 备选 / 质量复核 | 为什么分开 |
| --- | --- | --- | --- |
| 中文口播转写 | 阿里云百炼的录音文件转写/ASR 服务；评测候选为其[模型列表](https://help.aliyun.com/zh/model-studio/models)中的 `qwen-audio-3.1-asr-flash-filetrans` | 选择同平台另一款支持所需时间戳的转写服务，或腾讯云语音识别 | 口播保护需要可靠的句/词级时间轴，不等同于视觉理解；评测时检查方言、环境风声、多人发言 |
| 画面语义匹配 | 阿里云百炼 `qwen3-vl-plus` 作为**待测候选**：仅处理口播对应片段的少量关键帧 | 同一国内平台的其他低成本视觉档或国内其他平台，先做 A/B 再选 | [官方图像与视频理解文档](https://help.aliyun.com/zh/model-studio/vision)有多图和视频理解示例；先抽帧，不默认上传整段视频 |
| 故事线 / 结构化排片 | 国内可用的低成本文本模型作为待测候选；排片硬约束在本地执行 | 人工排序、本地规则回退 | 只对转写文本与候选摘要排序，不让模型生成新口播或自行删除句子 |
| 音频与实际导出 | 本地说话检测、波形/停顿识别 + AVFoundation | 无云端编码依赖 | 视频质量、源声是否连续及授权状态必须由本地校验 |

先在**阿里云百炼一个平台**完成口播和视觉两条试点，降低 SDK、账户和授权复杂度；但具体 API、模型 ID、时间戳粒度和价格必须以你开通地区与控制台的实时说明为准，不硬编码为永久默认型号。阿里云的[模型列表](https://help.aliyun.com/zh/model-studio/models)能核对候选名称，[图像与视频理解](https://help.aliyun.com/zh/model-studio/vision)文档能核对多图/视频输入方式；这**不等于**已验证上述 ASR 候选能直接输出稳定的词级时间戳。若没有，须补强制对齐或改用支持时间戳的国内转写服务，未达标前不开放“自动删除口播”。

本版方案不报未经核实的人民币单价。计费按 `音频时长/转写费 + 发送关键帧的图片 token 或图片请求费 + 文本整理与输出费 + 重试费` 估算，每个任务显示本次音频分钟数、待发图片数、预计费用范围与用户设定上限。成本优化的优先级是：转写结果按音频指纹缓存 → 本地筛出无声/重复画面 → 仅向视觉模型提交口播语义无法匹配的关键帧 → 将少量低置信片段交高质量档复核。不能为了省钱漏掉需要保留的人声。

上线前用**同一组用户授权的 Vlog**做模型盲测，记录 `口播句子漏识别率 / 完整语句保留率 / 音频断裂次数 / 单项目实付费用 / 处理时间 / B-roll 被用户保留比例`，优先淘汰漏口播或断句严重的路线，再比较性价比。价格表做成可更新配置，写明供应商、模型 ID、计费单位、地区、更新时间及来源；无法读取官方价格时显示「估算不可用」而非编造数字。API Key 只放 macOS Keychain，不进入项目文件、草稿或日志。

隐私原则：默认不联网、不上传原视频、不上传完整 FIT 或整个项目目录；国内云端口播转写和关键帧分析均需明确授权，界面分别显示待上传音频总时长、关键帧数量、画面中的时间/轨迹可能泄露位置。用户未授权时只做本地语音区间检测与人工标注；不能同时承诺本地模式一定能完整理解每句口播。处理方针、数据保存期限和平台所在地区需在上线前按最终选定厂商的实际条款核实。

## 5. 技术设计与数据结构

基于当前 macOS SwiftUI + RunOverlayCore + AVFoundation 架构新增 `SmartEditProject`（独立于已有 `.runoverlay` 的视频蒙层项目状态）：

```text
SmartEditProject
  sourceExports[]: 原导出文件 URL/安全书签、文件校验信息、尺寸、时长、
                   对应的原视频 ID、匹配后的运动起始时间、来源是否经用户确认
  options: 可选的建议时长（默认不填）、画幅、Vlog 节奏、口播保护、配乐、
           国内模型/上传授权与预算
  speech[]: 原声源文件 ID、语句/词级起止时间、转写稿、说话人、
            是否本人口播/待确认、用户锁定及人工修改记录
  analysis[]: B-roll 候选起止时间、视觉/运动事件特征、与口播语义的匹配分与解释
  timeline[]: 口播音轨片段 + 画面片段（分别引用源 ID 和入/出点）、
              顺序、锁定状态、音量包络及淡入淡出
  styleProfile: 本人确认过的口播占比、段落安排、镜头长度与配乐避让偏好
```

分析先由 AVFoundation **独立提取导出片的真实音轨、抽帧并读取时长**；无音轨时标记「无口播可分析」。云端语音稿返回后与原声音频时间轴对齐，界面预览时直接试听原声，不播放模型生成语音。采用受控 JSON 解析模型返回，丢弃越界时间、未知文件 ID、负时长、不连续的时间映射与不可信的置信度。按照文件哈希/音频指纹及模型版本缓存分析结果，相同素材不会反复计费。时间线预览用代理媒体快速拼接；最终由 `AVMutableComposition` 等本地合成方案将**口播音轨与画面轨独立排布**，统一分辨率/帧率/颜色空间并处理音量和方向，写入新文件，绝不覆盖已有导出视频。竖屏与横屏混合时先提示用户改比例或选择留黑，避免蒙层或人脸被裁掉。若导出片已经有黑边，不叠加第二层黑边。

需支持三类错误恢复：安全书签或目标目录授权失效（提示重选并做实际写入测试）、网络/模型调用失败（保留本地分析草稿）、渲染取消或空间不足（保留编辑项目与既有输出，清理临时文件）。分析和渲染独立进度，允许后台继续；正在渲染的时间线快照固定，不受用户下一步编辑影响。

### 成果清单和剪辑草稿如何保存

新增独立的、带版本号的 `ExportedClipManifest`，由 `AppModel` 在**导出成功且输出文件可读**时更新。它不依赖已经清空的运行时导出队列，至少记录 `projectID / originalVideoID / exportedURL + 安全书签 / 输出文件名、体积和持续时间 / 拍摄开始与校准偏移快照 / 导出时间 / 导出画幅`。文件元信息用于变更检测，不作为视频相同的唯一判断。用户手动选择历史导出片时，明确标记为「来源待确认」，确认后才允许使用 FIT 事件关联。对于已录入的剪辑工程，关闭后重新打开仍能正确重连原导出片。

本地内部索引放在应用支持目录，跟随项目 ID 管理；用户执行「项目连素材打包」时，把清单和已保存剪辑草稿一并包含在包内，并改写包内相对路径。不要未经用户明确选择就复制所有带蒙层导出视频，因为这可能把项目包扩大数 GB。单视频输出文件被移走时弹出重连提示，而不是悄悄重新导出或用同名文件顶替。

剪辑草稿的 `timeline` 用导出片 ID 和源片内秒数作唯一时间轴坐标；**语音和画面分别记轨道及时间映射**，以便画面换镜而口播不中断。由导出时保存的捕获时间 + 偏移**快照**计算运动事件。后来用户重新校准原片时间，不应偷偷改变已保存成片的运动事件；如需更新，提供「按新的运动数据重新分析」明确操作。用户锁定的口播句子、亲自移动的片段和手动修订的文字稿，重新生成时均不能被模型覆盖。

### 第一版产品界面

主工作台右上角增加独立「智能成片」入口，不挤占原批量导出按钮。页面保持现有三栏设计语言：左侧已导出素材和原声音轨/缺失状态，中间视频与两条独立的「口播音轨＋画面」时间线，右侧画幅、Vlog 节奏、可选建议时长、国内云服务授权/预算；时长控件默认为「由素材决定」，当前草稿实际总时长由时间线实时计算显示。口播句子以高亮条显示转写文本，锁定时有明显标识；可按句试听、确认说话人、改字、保留或请求删除。底部保留播放和单帧定位。每个 B-roll 候选有与口播对应的推荐理由及「使用/锁定/排除」操作；全局有「本地生成草稿」「国内 AI 分析」「预览」「导出成片」。禁用按钮时给出具体原因，比如「尚未确认口播说话者」或「所选画幅会裁掉轨迹」，不以变量名充当文案。

## 6. 分阶段交付与验收

**工程底座（首个可试用版之前）**：建立导出成果清单与手动关联，导入已导出视频，搭建可保存的双轨剪辑草稿、本地说话区间检测、原声持续播放与画面直切。离线时可手动标注口播并生成保守草稿；这一阶段是内部开发步骤，**不能作为已满足“AI 自动剪辑”的版本交付**。

**首个可试用版（接入国内大模型）**：在工程底座上接入经用户授权的国内 ASR 与视觉模型。ASR 转写语句并对齐时间，用户确认本人说话者；视觉模型只读经本地筛选的关键帧，将 B-roll 匹配到真实口播。界面给出建议理由、音频/图片分别授权的开关和费用预算；输出由素材决定时长的可编辑 Vlog 时间线。口播不能被模型直接删除，需人工确认；无模型或断网时仍能回退本地标注与导出。用含真实口播的素材验收音画连续、画面切换时原声不中断、蒙层和比例正确；现有两段大疆 demo 可辅助测试画面与 FIT 匹配，但不当作完整的口播质量样本。

**质量增强与性价比评测**：用至少 20 段含本人清晰口播、风声和人群声的 Vlog 测试漏句、断句、补画面匹配、实际费用和总耗时。比较国内服务商及同服务商的不同档位，达到可接受质量后再确定正式默认模型、进一步优化镜头建议；未验证实时价钱前不承诺固定费用。

**个性化**：加入本人 Vlog 成片参考和风格轮廓，学习用户常保留的口播占比、说话节奏、插入跑步/风景镜头的时机、转场克制度及开场/结尾偏好；允许手动调整并一键重置。对同一批素材做盲测；未获得足够口播样片时不声称「已学会你的风格」。

**建议验收门槛**：所有生成片段都能定位原视频与原始时间、没有被意外删除的本人整句口播、没有句首/句尾被截断或背景音乐盖过人声、画面切换时口播持续；无黑帧/静音意外、运动里程不倒退（除用户显式选择倒叙）、轨迹/数字不被裁掉；无时长硬上限，草稿时长按实际片段计算，修改后能导出。后台分析和渲染不锁死现有单视频操作，断网仍可人工标注并生成本地草稿，未经授权时不发媒体请求。多人、风噪、方言、极短口头语与口播跨镜头连续性都需作为独立验收样本。

### 可直接拆分的实施顺序

1. **成果关联与迁移**：为成功导出添加成果清单，关联源视频 ID、快照时间/偏移、输出 URL 与书签；给历史视频提供「选择导出片并确认对应关系」入口。确保源文件失踪时有重连提示。
2. **口播与双轨时间线最小闭环**：本地检测说话区间、用户确认本人声音；时间线分别引用口播音轨与画面片段，支持句间切画面、片段锁定和撤销；用包含清晰本人讲话的真实素材验证连续口播及导出音画同步。
3. **国内模型与隐私门禁**：在首个可试用版中加入国内 ASR/视觉能力适配、明示音频与关键帧上传的独立确认、Keychain 密钥与费用上限；完成本人说话者确认后，把口播语义与画面候选匹配，结果通过本地约束验证才能进入时间线。
4. **本地候选引擎**：代理文件、画质/重复度筛选、按 FIT 事件提名、口播语义匹配和断网保底；给补画面候选展示原因和来源时间。
5. **风格学习与素材验收**：用户给出 2～5 条喜欢且保留口播的 Vlog 或真实时间线，建立可编辑个人风格轮廓，用不同人声环境做盲测。

## 7. 开发前需要你的两项素材与一个偏好

1. 你认可的 2～5 条本人剪好的**有口播**跑步 Vlog；最好附原素材或剪辑时间线。没有的话先用「保留口播」预设，后续根据你在草稿中保留/删除口播与补画面的行为学习。
2. 一批实际准备剪的、已导出且保留**你的原声口播**的视频，用于验证转写与音频保留；目前 `demo/result` 为空，不能以它已有成片作为前提，也不能确认现有两段大疆 demo 能覆盖风噪、多说话人和完整口播测试。
3. 其他可选默认值：沿用素材原始画幅、优先保留所有本人讲话和现场声、音乐默认关闭；本人语音转写由用户授权后调用国内模型，断网时才回退本地标注。**时长始终默认「由素材决定」**；其他设置都可由你调整。

已确认的产品决定：**不限制视频时长、使用国内无需翻墙的模型、以 Vlog 为主题并优先保留本人原声口播**。暂按「原始画幅、无背景音乐、先本地检测说话区域，再经授权调用国内 ASR 和视觉模型；断网时人工标注」作为建议流程；如需改成默认加音乐或指定竖屏，开发前再调整。
